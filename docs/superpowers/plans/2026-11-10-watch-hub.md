# Watch Hub + Signal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the watch's single long contact list with a hub home (search, 3 latest calls, app buttons) plus one list per app, keep history current, badge recent calls with their app, and prove Signal voice through the watch.

**Architecture:** Pure-Java helpers (`AppLists`, `AppBadge`) hold the logic and are unit-tested in plain JUnit. Row binding moves out of `MainActivity` into `PersonRows` so the home and the new `ContactListActivity` share it. `ContactListActivity` reuses `activity_main.xml` (recycler, message, A–Z strip). Signal voice is a field test on the owner's devices at the end.

**Tech Stack:** Java 21, Android views (`WearableRecyclerView`, XML layouts), JUnit 4 + Robolectric (`WatchScreensTest` renders PNGs to `wear/build/screens/`), Gradle.

**Spec:** `docs/superpowers/specs/2026-11-10-watch-hub-design.md`

## Global Constraints

- Build/test with `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"` (JDK 21); the system JDK 26 fails with "invalid source release: 21".
- Watch tests: `./gradlew :wear:testDebugUnitTest`; phone tests: `./gradlew :app:testDebugUnitTest`.
- Every new string in `wear/src/main/res/values/strings.xml` **and** `values-it/strings.xml`.
- No numbers or photos sent to the watch; names only.
- No new phone↔watch protocol messages.
- Tile, complication, `InCallActivity`, phone UI: unchanged (except Task 6's `SupportedApp.SIGNAL` flags and README).
- App keys on the watch: `Protocol.WHATSAPP`, `Protocol.TELEGRAM`, `Protocol.SIGNAL`, `"com.instagram.android"`.
- Commit only when the owner has asked; until then, end each task with the suite green and leave changes staged-ready (the "Commit" steps below run once the owner says to commit).

## Review Focus

1. **Owner returns to home after a call** while it was in the background → the new call is at the top (Task 4 test `resumeShowsNewCall`).
2. **Typing in search when a background reload lands** → keyboard stays open, results not replaced by the hub (Task 4 test `reloadKeepsSearchResults`).
3. **Recent call from someone not in contacts** (contactId −1, e.g. Signal stranger "Unknown") → tap shows the existing `cant_call_back` toast, no crash (Task 3 test `recentStrangerCantCallBack`).
4. **Person on WhatsApp and Signal, opened from the Signal list** → calls on Signal, no picker (Task 3 test `appListCallsThatAppDirectly`).
5. **No favourites, no Signal contacts** → those buttons hidden, remaining buttons laid out without gaps (Task 2 test `buttonsSkipEmpty`, screen `8-hub-two-buttons`).
